## GPU 小检查

使用现有 Qwen3.5-4B 基模及随机初始化 decoder，不是 Xiaomi-Lens-0 公开训练权重。
本次共完成 2 次 GPU 参数更新，分别使用真实 RGB 与 RGB+DEM+encoded InSAR 样本。

| 项目 | 实测 |
| --- | --- |
| GPU | RTX 4090 D，约 24 GiB；检查启动时空闲 24,154,996,736 bytes |
| 处理后图像网格 | 2×2 patch，即 32×32 处理画布；原样本为 224×224 |
| 训练峰值分配显存 | 10,590,146,048 bytes，约 9.86 GiB |
| 两次更新耗时 | 12.33 秒，不含读权重和完整身份核验 |
| 全部资源检查耗时 | 121.57 秒，包含权重身份核验、加载与附加检查 |
| 可训练参数 | 85,172,704，包括 decoder、辅助融合和语言 LoRA |
| 两次总损失 | 11.6752796173、10.9447202682；样本不同，不能据此声称训练收敛 |
| 受提示解码输出 | 恢复为 224×224，前景 22,681 像素；不是自由生成成功 |
| 自由生成检查 | 只生成 8 tokens，未完成回答，未生成 mask token；如实记为未验证自由分割能力 |

低分辨率结果不能证明高分辨率训练可在同样显存内运行，未独立测量完整区域反馈与 RAG 的 GPU 峰值。
后续发现慢图像处理器会保留旧像素上限，已同时设置两套参数并加入实际网格断言。
另行复查确认本次 4B 使用的快处理器前后都是 2×2 网格，以上 GPU 记录不受该修正影响。

证据位于工作区 `research_runs/base4b_probe/report.json`、`delta/` 及明确命名的受提示解码 PNG。
新增资源脚本用于以后复现，本次 GPU 更新预算已用完，不自动重复。
