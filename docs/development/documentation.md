# 文档维护规则

[返回本节目录](README.md) · [文档总目录](../README.md)

## 修改与同步

讨论方案时保持讨论，确认后才把实现与文档一起修改。写入说明必须区分“设计要求”“实际行为”“尚未完成”。文档同步不能替代研究设计变更授权。

| 修改内容 | 同步位置 |
| --- | --- |
| 算法行为、输入与输出约定 | architecture 对应主题；usage 中受影响的说明 |
| 命令、配置、安装或部署方式 | usage 对应主题 |
| 数据要求、训练或评价流程 | architecture 与 usage 对应主题 |
| 当前成果、失败原因、验收结果、下一任务 | status 对应章节 |
| 讲解和演示材料 | ppt 对应章节，链接当前状态 |
| 文件移动、新增或删除 | 所属目录和所有活动引用；必要时更新根目录 |

交付前逐项对照实际改动。没有文档变化时说明原因，不用机械修改日期制造同步记录。

## 信息只维护一处

设计、使用、状态、讲解各有职责。成果数字和身份以 status 为唯一入口；讲解中的展示数字是制作素材，制作时从 status 核对，不能成为另一套进度。

README 和各级目录只写概要及链接。正文原则上每篇不超过 200 行，目录页不超过 100 行。每篇都有返回目录和相关章节链接。长表按主题拆分，不将完整正文塞回目录。

## 历史与来源

历史方案原文完整保留在 archive，不再充当活动使用说明。版本关系和旧路径映射在归档目录维护，不改写原文修补旧链接。

原始附件、知识 PDF、模型附带说明、程序提示词和实验输出不受普通正文篇幅要求约束；未经授权不得移动模型、数据或实验资产。

## 当前状态更新

新状态直接更新所属章节，不按日期堆积工作日志。正式成果保留根目录、身份和验证依据。已解决的一次性失败不占据当前概要；仍阻塞工作的原因保留在下一步章节。

人工复查见[检查清单](review.md)，操作边界见[AGENTS](../../AGENTS.md)。
